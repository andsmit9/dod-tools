- **PatcherConfig Mocking:** When mocking `PatcherConfig` for tests evaluating `build_batch_queue()`, `config.primary_media_dir` must be explicitly populated with a valid `Some(PathBuf)` (e.g., pointing to a temporary directory). Failing to provide this specific field triggers a "Target game output directory not found" panic, which is easily misattributed to `config.game_path`.
- **Batch Queue Primer Injection:** When writing assertions against the output vector of `build_batch_queue()`, always account for the engine unconditionally injecting a `Primer` job at index 0 (if `total_jobs > 0`). If your test mocks `X` distinct groups of `CaptureStreak`s, the resulting `PatchJob` vector length will always be `X + 1`.
- **Localization Key Canonicalization:** Localization tokens are stored **bare** — lowercase, no `#`. The `#` is a lookup-time sigil, not part of the token name, which is Valve's own convention: every shipped game file (`dod_english.txt`, `valve_english.txt`, `gameui_english.txt`) stores keys without it, as do AMXX files by format. `localization.rs` normalizes on both insert and lookup via `normalize_key`, so a file written either way resolves identically. Earlier the loader stored keys verbatim and `translate_key` only ever *prepended* `#`, never stripped it — which meant every `#`-prefixed query against the game's own 1,190 bare-stored tokens silently returned `None`, and chat, class and score strings rendered untranslated. Do not reintroduce `#` into key names in `dod_studio_english.txt`.
- **Immediate-Mode Panel Hoisting:** Contextual footers (`TopBottomPanel::bottom(...).show_inside(...)`) and overlay panels must be hoisted to the absolute top of the rendering function to avoid being short-circuited or hidden by modal file pickers or asynchronous loading early returns.
- **Immediate-Mode UI Dialog Concurrency:** Asynchronous background tasks (such as mass file ingestion loops) that yield control to OS-level file dialogs require persistent, dedicated status panels or background worker cancellation channels rather than relying on inline layout components that disappear during modal yields.
- **Closure & Delimiter Safety in egui:** Large immediate-mode refactors involving nested closures (`ui.add_enabled_ui`, `TopBottomPanel`) are prone to unclosed delimiters; verify closing braces explicitly against open bracket counts to prevent EOF errors.
- **1:1 Immediate-Mode Mapping Friction:** Never attempt to translate an immediate-mode GUI (`egui`) 1:1 into a declarative DOM (`Vite`) environment. Structurally decouple state from visual components and utilize standard web layout paradigms to prevent rendering loops and layout collapse.
- **Cargo Implicit Binary Auto-Discovery:** When deprecating a binary target in a workspace (e.g., legacy `egui` gui), deleting the `[[bin]]` block from `Cargo.toml` is insufficient. Cargo auto-discovers implicit binaries in `src/bin/`. The dead directory must be physically deleted from disk to prevent unlinked crate compilation errors.
- **Local Tauri CLI Execution:** In a Vite-scaffolded workspace without a globally installed `cargo-tauri` CLI, native rust execution commands (`cargo tauri dev`) will fail. You must route execution through the local Node dependency wrapper (e.g., `npm run tauri dev` or `npx tauri dev`).
- **Tauri Runtime Pathing Resolution:** Tauri dev and release binaries execute deep within `src-tauri/target/...`. Standard relative pathing (`../`) fails to locate workspace-root folders (like `localizations/`). Path resolution for static workspace assets must actively walk up parent directories (up to 6 levels) instead of relying on a fixed relative depth.
- **Global CSS Reset Traps:** Applying `appearance: none` globally to all inputs silently strips native rendering for `<input type="checkbox">` and `<input type="radio">`. The elements remain in the DOM and respond to JS click events but are visually blank. Exempt these types or apply specific fallback styling (e.g. a themed `accent-color`).
- **sysinfo 0.30 `Process::name()` Signature:** At the `sysinfo = "0.30"` version this workspace resolves to (0.30.13), `Process::name()` returns `&str` directly. Calling `.to_string_lossy()` on it is a compile error (`E0599`, no such method on `&str`) — pass the slice straight to string-matching helpers instead.
